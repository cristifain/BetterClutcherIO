QUICK FACTS
-----------
The game ships with two maps:

    dusker   display name "Dune" - Desert Town-ingame   (dust2-style skybox)
    oasis    display name "Oasis" - Palace-ingame  (mirage-style skybox)

Map geometry/data live in  assets/models/  (per-map file set, see section 3).
Map definitions/logic live in  src/main.js  (see section 2).
Line numbers below refer to the current working tree and may drift as code
changes - the anchors (object names, strings) are what matter.

3. MAP ASSET FILES - assets/models/
-----------------------------------
Per-map naming convention (<map> = dusker | oasis):

  <map>.glb                 main visual mesh, desktop quality. Materials carry
                            lightmap UVs on channel 1 (uv1).
  <map>_mobile.glb          reduced mesh, used on mobile / low quality.
  <map>_data.json           JSON: world bounds, spawn points (spawnsT/spawnsCT
                            with x/y/z/yaw/priority), bot waypoints, and a
                            grid of collision boxes.
  <map>_phys.bin            binary collision meshes ("D2P2" format, see Dy()).
  <map>_lightmap.jpg        baked lightmap texture (aoMap/uv1).
  <map>_shadows.png         baked shadow overlay.
  <map>_shadows_mobile.png  shadow overlay for mobile/low quality.
  oasis only:
    oasis_entities.json     destructible prop templates (breakable clay pots
                            etc.). Generated by tools/cs2_entities.py - the
                            tools/ folder is NOT in this repo.
    oasis_props.glb         prop meshes used by the entities system.
  Skyboxes (wired in cfg.sky / cfg.skyMobile):
    sky_dust2.jpg  (+ _mobile)   -> dusker
    sky_mirage.jpg (+ _mobile)   -> oasis

  NOTE: the path strings in main.js are obfuscated. They are decoded at
  runtime by __p_KGFS_MAIN_STR(start, len) from src/decode.js. Decoded
  values (verified):
    dusker cfg  main.js:25737+  ->  ./models/dusker.glb
                                    ./models/dusker_mobile.glb
                                    ./models/dusker_data.json
                                    ./models/dusker_phys.bin
                                    ./models/sky_dust2.jpg
                                    ./models/dusker_shadows.png ...
    oasis  cfg  main.js:26340+  ->  ./models/oasis.glb
                                    ./models/oasis_data.json
                                    ./models/oasis_phys.bin
                                    ./models/oasis_entities.json
                                    ./models/oasis_props.glb ...
  To dump ALL decoded strings yourself:  node _decode_all.js  (repo root)


4. HOW ASSET URLS RESOLVE (important before moving anything!)
-------------------------------------------------------------
src/main.js:2506-2515  - the THREE.LoadingManager URL modifier (Mr):

    any loader path starting with  models/  textures/  tex/  inputs/
    (or ./models/...)  is rewritten to  assets/<path>

So the LIVE asset root is the local  assets/  folder:
    ./models/dusker.glb          ->  assets/models/dusker.glb
    textures/fx_tracer.png       ->  assets/textures/fx_tracer.png

The var jr (main.js:2300) still references the original CDN
(https://assets.clutcher.io/, with per-file hash map), but the current
URL modifier does NOT use it - everything loads from assets/.

Audio is different: audio.js:13 fetches  sounds/manifest.json  RELATIVE TO
THE PAGE ROOT (not rewritten), so the live sound folder is the root-level
sounds/, and root-level textures/ is NOT the live texture folder.


5. REPLACING MAP ASSETS (drop-in)
---------------------------------
Easiest -> keep the exact filename and replace the file in assets/models/:

    new dusker geometry    -> overwrite assets/models/dusker.glb
    new collision          -> overwrite assets/models/dusker_phys.bin
    new spawns/waypoints   -> overwrite assets/models/dusker_data.json
    new sky                -> overwrite assets/models/sky_dust2.jpg
    ...

Rules of thumb:
  - Always update <map>_phys.bin together with <map>.glb, or players fall
    through / clip into new geometry (visual mesh and collision are separate).
  - <map>_data.json spawns need x/y/z + yaw (+ priority); waypoints feed bot
    navigation; boxes feed the coarse collision grid.
  - Lightmap goes on uv1 - re-bake or the lighting will look wrong.
  - Keep a *_mobile.glb variant, or mobile/low-quality players will still
    stream the heavy one (check quality/mobile flags around loadMap()).
  - Changing world bounds? Update <map>_data.json "bounds" AND the server's
    MAP_MIN_Y/MAP_MAX_Y fallback (betterclutcher-server/src/index.js:26) is
    generous (-64..256) so only extremes matter there.


6. ADDING A NEW MAP (checklist)
-------------------------------
 1. assets/models/<id>.glb + <id>_mobile.glb + <id>_data.json +
    <id>_phys.bin (+ optional lightmap/shadows/sky files).
 2. src/main.js: copy the ky map object, give it id "<id>", set cfg paths
    (plain strings are fine in new code - the decoder is only needed for the
    original obfuscated ones), keep/reuse build().
 3. Register it in the map registry Hx (src/main.js:28264).
 4. Add it to the menu picker (src/main.js:29221 area).
 5. Server: allow the map name in betterclutcher-server/src/index.js
    (matchmake filter at :104 and the /quickmatch regex at :677), then
    npx wrangler deploy from betterclutcher-server/.
 6. If bots should work: make sure the data json has waypoints and the
    surfaces/bombsites exist - defuse mode indexes map.bombsites.

                          { "addammo_ak47": ["addammo_ak47.m4a"], ... }.
                          Sound event definitions (pitch/curve data per
                          weapon) are in src/data-BdgATJBp.js.
  assets/sounds/          mirror of sounds/ - not fetched by the client.
  ui/                     UI images: ui/skins/, ui/paints/, ui/cases/,
                          fonts (Stratum2), avatars, scorebar art.
  icons/                  weapon/equipment SVG icons for HUD/buy menu.
  src/cases.js            42 crate definitions: id, name, price, contents,
                          odds. Re-exported by data-BdgATJBp.js.


8. TOOLING / CAVEATS
--------------------
  - node _decode_all.js  dumps every __p_KGFS_MAIN_STR(start,len) string in
    src/main.js (asset paths, UI strings, ...). Useful to find where a
    hardcoded string lives - output format: "0x1bc20,0x18 => ./models/...".
  - main.js is decompiled/obfuscated original code (short names, hex
    literals). hud.js / bots.js / pviewmodel.js / audio.js / paint-system.js /
    pcrossair.js / decode.js are verbatim extractions from it - their header
    comments explain what each contains.
  - Uncommitted edits exist (hud.js, netcode.js) - re-check line anchors
    after committing.
